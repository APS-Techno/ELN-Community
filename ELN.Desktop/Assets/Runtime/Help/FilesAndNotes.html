Files and notes

Attachments belong to an item. Open a notebook, select an active project, then select the parent item. Signed items cannot have their attachment bytes changed. A read-only or archived project also blocks content changes.

Attach local files

  1. Choose Item > Add File, or click Add File. Select the source files in the file browser.
  2. For one ordinary file, check or change Attachment file type and Display name in the browser, then click Attach. There is no second dialog for that file.
  3. For multiple files, click Review files to open Files to attach. Check each Source filename, Display name and Type. Select each row to change Selected file type.
  4. In the multi-file review, keep Keep display names, or select Use prefix: and enter a prefix for numbered names. Click Attach.
  5. Check the attached files in the item tree. Each source file is copied into notebook attachment storage; the source is not moved.

The file browser shows a folder icon for directories and a document icon for files. Double-click a folder, or select it and press Enter, to open it.

A selected deposition file can expand to a related file pair. That expanded selection also opens the multi-file review, even if you initially selected one source.

Every selected file needs a valid file type and name. Register a missing type in Reference Data. If a copy fails, the failed attachment record is removed and remaining files are skipped. Earlier files in that batch may already be attached.

Attachment names omit the registered extension. For compound types such as .depo.json and .process.log, the suggested display name omits the whole suffix, not just .json or .log. Check both the name and the selected type before attaching. Adding a file copies its bytes into notebook storage; it does not move the original or copy other item attachments into the source folder.

View or open an attachment

Click a thumbnail to show its working copy in the content viewer. Double-click an attachment or thumbnail to open it. Markdown uses the Markdown editor when that plugin is loaded. Other files normally open with their Windows application unless their selected plugin requests internal opening.

The Protocol viewer displays protocol forms; it is not a general file editor. Preview support depends on the loaded plugin and the file format. An extension match does not guarantee that all content can be parsed.

The compound extension selects the specialist reader: .depo.json uses Deposition rather than the general JSON viewer. Its preview shows the Overview tab. Recipe and process-log attachments have their own file-type icons. X-Ray Calc displays project structure and reflectivity content; Recipe displays recipe content, and Process Log displays process events. Reader output depends on the content that is present in the file. Use Extract Values to inspect the available numeric results rather than assuming that every viewer provides the same keys.

For ZRW friction results, see ZRW friction coefficient. That guide explains the coating plateau, Manual and Automatic intervals, Apply, Reload and stale selections. The same guide explains reader conversion, standard deviation and source checks.

The MIT viewer shows the indents of a .mit file in the list Records: and the force-depth curves in a chart. The FIBPS and VK4 viewers show a height map. Both have the tools Profile, Distance, Roughness and Flatten. The VK4 viewer has a Channel: list. The FIBPS viewer also has Step Height and Wear Track. For the MIT results, see MIT nanoindentation results. The MIT, FIBPS and VK4 readers use our own analysis of measurement files and contain no vendor code. APS is not affiliated with or endorsed by Anton Paar, KLA/Filmetrics or Keyence. The names identify file compatibility only.

Stored bytes and working drafts

Opening an attachment creates a separate local working copy. The path shown by the host is not the stored attachment. Saving in an external application changes that working copy first. Do not edit notebook storage files directly.

  1. Finish saving in the external application.
  2. Select the attachment and choose Tools > Save Attachment Working Draft to copy changed working bytes back to the notebook.
  3. To discard the working copy and load stored bytes, choose Tools > Reload Attachment Working Draft. Close separate editor windows first. Confirm the discard prompt only if you do not need their edits.

If the stored attachment changed after the draft was opened, the host asks: Yes overwrites the current attachment with the draft; No starts reload and discard confirmation; Cancel keeps the draft without saving. Neither overwrite choice bypasses signed-item or project write restrictions.

On notebook close or exit, the host asks only about changed attachment working files, not about saving the notebook database. Cancel stops closing. No leaves the attachment draft at the path shown in that prompt. Normal shutdown has no separate working-directory notice. A failed attachment save identifies retained draft or recovery paths; keep those files if recovery is needed. Retention is not a notebook backup.

Markdown editor

Use Edit in the Markdown viewer, or open a Markdown attachment. Edit the source and click Save or press Ctrl+S. A successful save updates the stored attachment through the notebook service. The editor writes its local file before it requests that save, so a failed or cancelled save can leave useful draft bytes.

Its conflict dialog still uses server wording in Community. Here, “server” means the notebook attachment, not a remote server:

  • Cancel: keep your edits without replacing stored bytes.
  • Reload (discard my edits): replace the draft with the current stored attachment.
  • Save Anyway (overwrite server): explicitly replace the current stored attachment with your draft, if write checks permit it.

Reload also discards unsaved editor text after confirmation. Close prompts use Yes to save, No to discard unsaved editor text, and Cancel to keep the editor open. See Wiki for Markdown assets and navigation.

Replace, rename, move or delete

  • Right-click a file and choose Reupload.... In Select replacement file, choose the new source. This replaces stored bytes, not just the current draft. A changed version or hash can refuse replacement; refresh before trying again.
  • Use Edit in the file context menu, or select the file and click Edit, to change its title and description. Rename can also move its stored bytes. A stale metadata version must be refreshed before renaming.
  • Choose Move to..., select a destination item from the current item list, then click Move. The destination must be writable and unsigned. This changes ownership of the attachment and can relocate its stored bytes.
  • Choose Delete and confirm to remove the attachment record and stored file. This is not a Recycle Bin operation.

When a replacement filename ends with the attachment's current compound extension, Reupload... keeps that type. For example, replacing a .depo.json attachment with another .depo.json file does not change its type to general JSON. Check the resulting type and preview after replacement.

You can select several files in the item tree. Move to..., Export and Delete then work on all selected files, with one confirmation and one summary. Files of signed items are skipped. Export asks for a folder. If a file name already exists in the folder, the new file gets the suffix (2), (3) and so on. Export never overwrites a file. Delete removes files and notes permanently. It also removes the Reader values that were extracted from the deleted files into their item. The confirmation shows how many values it removes. Manual values stay. See Values.

Back up needed files before replacement or deletion. Resolve editor drafts before rename, replacement or move. Conflict handling protects draft saves; it does not promise safe simultaneous physical file moves. Do not use two processes to reorganize the same attachment storage at the same time.

Add and edit a note

  1. Select an item and choose Add Note. A selected file or entry can also supply its parent item.
  2. Enter a nonempty Title: and the note text. Use B, I and U for selected-text formatting.
  3. Click OK to save, or Cancel to leave the dialog.
  4. Select the note to preview it. Double-click it, or use Edit, to change it. Delete removes the selected note after confirmation.

Notes store rich text as notebook entries, not as Markdown attachments. Signed parent content has write guards. See Items, Protocols and Integrity.
