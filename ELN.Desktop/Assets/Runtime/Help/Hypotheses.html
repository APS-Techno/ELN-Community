Hypotheses

A hypothesis connects a proposal, experimental runs, cited evidence and a conclusion. Open a notebook, select an active project and choose Project > Hypotheses.

Propose and review

  1. Click New hypothesis....
  2. Enter Title and Statement - what you expect, and why. Select a headline quantity if you want a key value summary over runs. Click OK.
  3. Select the proposal and read the Proposal tab. Use Edit... while it waits for approval.
  4. In Your decision, read the proposal and choose Approve or Reject. A rejection requires a comment.

Use New follow-up... on an eligible hypothesis to propose a child. Explain Change - what differs from the parent hypothesis. A follow-up is a new proposal; it does not overwrite the parent.

Community uses local human review. The active local scientist can review their own hypothesis in an active owned project. This is not multi-user authorization or independent team approval. MCP can prepare hypothesis records, but cannot approve, reject, accept or return them. Perform these human decisions in the desktop.

Attach runs and references

  1. Select the scientific item in the item tree. Open the project's Hypotheses view again if the item selection closed it.
  2. Select the hypothesis and open Runs.
  3. Click Attach selected item.... Check the item title in the dialog and choose Run or Reference when offered.
  4. After approval, attach actual run records. Before approval, only Reference is available.

A Run connects experimental work to this hypothesis. A Reference supplies context. Read the Attached as and Warning columns. Double-click a row to open its item. Remove detaches the association; it does not delete the underlying item.

Cite evidence

  1. After proposal approval, open Evidence and click Add evidence....
  2. In the left list, select an attached Run or Reference, or an indented live descendant. A measurement action below a run can supply evidence without being attached as a separate Run.
  3. In the right list, select the item itself, one of its files or one of its values.
  4. Enter a note that explains the citation, then click OK.
  5. Check the selected evidence and any warning. Use Remove to remove a citation, not the scientific source record.

Submit and accept a conclusion

  1. Inspect the runs, evidence and warnings before you conclude.
  2. Open Conclusion. Enter What we found. Select Supported, Refuted or Inconclusive under Outcome.
  3. Click Submit conclusion. The status becomes Needs acceptance.
  4. Read the submitted conclusion and cited evidence. Choose Accept, or Return for more work with a comment. After return, revise the work and submit again.

An accepted conclusion has a content seal. Read any seal or evidence-change warning; do not treat a warning as acceptance of changed data. History shows the decisions, dates and comments. A conclusion outcome is not automatic proof of causation.

Refresh and stop work safely

Click Refresh for current data. If a change makes a typed conclusion stale, read the draft notice and preserve the text before you continue. Do not force a decision after a version conflict.

Abandon... stops work and keeps the hypothesis as Abandoned. It does not erase its history. Hypothesis references can block unsafe deletion of items or evidence. See integrity and recycle safety and MCP.
