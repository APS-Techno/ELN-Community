Integrity and completeness

Review states, item signatures, audit events and completeness checks serve different purposes. None replaces a backup of the notebook and attachment directory.

Sign an item

Signing permanently locks the item against edits, additions and deletions. The application does not provide an undo for signing. Complete and inspect the record before you sign.

  1. Open an active project and select the item, not an attached file or protocol.
  2. Right-click it and choose Signature > Sign Item....
  3. Check Item Title. Select a Meaning: Authored, Reviewed, Approved or Witnessed.
  4. Enter a Comment when needed and the local scientist profile's Password.
  5. Click Sign. Read any password or signing error before you continue.

The password is checked against the local profile. A signature meaning is a recorded assertion by that local scientist. It does not assign team authority or prove an independent witness. A protocol's Approved state is separate from an item signature.

Inspect and verify a signature

  1. Right-click the signed item. Choose Signature > View Signature....
  2. Inspect Signed By, Date, Meaning, Comment and Content Hash.
  3. Click Verify Now. You can also choose Signature > Verify Integrity from the item's context menu.

Verification compares the current item hash with its stored signature hash. It covers selected item fields, attached entry content, stored file titles and hashes, and numeric values and tolerances. It is not a recursive signature of every child item, and it does not reread every attachment's bytes. Do not interpret VERIFIED as a complete storage check or proof that the scientific conclusion is correct.

If verification reports a mismatch, preserve the notebook and attachments. Do not change records to hide the warning. Check the signature and audit record, then investigate the affected content.

Inspect the audit log

  1. Choose Tools > Audit Log....
  2. Set the available From, To, Entity, Op and User filters.
  3. Click Refresh. Read Timestamp, Entity Type, Entity ID, Operation, User and Description.

The log records application events. It is not a full historical copy of every field or file, and it is not an external tamper-proof archive.

Define completeness rules

  1. Choose Tools > Completeness Rules....
  2. Click Add, or select an existing rule.
  3. Enter Title and Description. Select Action Type, Equipment and Severity as required.
  4. Check the Required File Types and Required Value Types. Set Active and click Save.

Use rules to express which record types must be present for the selected scientific work. Error and Warning are completeness severities; they do not automatically judge scientific validity. Use Delete only when the rule is no longer required.

Run a completeness report

  1. Select the project and folder to check.
  2. Choose Tools > Data Completeness....
  3. Read the Data Quality Check results: Category, Severity, Item, Location, Rule and Missing.
  4. Select a result and click Go To, or double-click it, to inspect the item.
  5. Use Export... to save a CSV report. Correct the record, then reopen Data Completeness to make a new check.

A report is a check at its displayed time. No findings does not prove that the experiment, units or interpretation are correct.

Recycle safety

Inspect Tools > Recycle Bin... before you restore or permanently remove deleted content. Signed items and hypothesis-linked evidence have safety restrictions. Do not bypass a refusal to remove a referenced record. Permanent removal is not the same as reversible deletion.

See projects and recycle actions, attachment safety, hypothesis seals and human decisions, and protocol review. Community human review is local, not multi-user authorization; MCP cannot execute human gates.
