Notebooks, identity and backup

Keep the database and attachments together

A complete notebook consists of its .sqlite database and its matching attachment directory. Keep the directory structure and filenames unchanged. Attachment metadata alone cannot restore missing file bytes.

The signing password is not a database-opening password. Protect the database, attachment directory, backups and retained drafts with operating-system access controls. Community is not an encrypted notebook or a multi-user server.

Open or switch a notebook

  1. Choose File → Open Notebook... and select the Community database.
  2. If the notebook has a saved attachment directory, it opens without more questions. If not, or if the saved directory is missing, select that notebook's attachment directory, not a directory from another notebook. Community then asks whether to remember it in the notebook. Click Yes to open the notebook without this question next time. Click No to leave the notebook unchanged.
  3. If another notebook is active, finish or cancel its pending editor and working-draft decisions. The candidate is validated before the active notebook is released.
  4. Check the notebook path and local identity in the main window before making changes.

To switch quickly, choose File → Recent Notebooks and select a notebook. The list shows up to eight notebooks that opened successfully, the most recent first. The active notebook has a check mark. Switching uses the same validation and draft decisions as Open Notebook. If a listed notebook file is missing, Community asks whether to remove it from the list. Clear Recent List removes all entries; it does not change any notebook.

On the same drive, the notebook saves its attachment directory as a path relative to the folder of the database, for example ..\Files when the database is in a DB folder beside a Files folder. On another drive, it saves the full path.

Opening does not create a database. The supported local format is version 5 and requires exactly one active identity. Commercial databases, unsupported local formats and SQLite WAL-mode databases need a separately controlled conversion; changing a marker or deleting a user record is not a conversion.

Upgrade a format 2, 3 or 4 notebook

When you open an older supported notebook, explicitly or as the last notebook at startup, Community asks before it changes anything.

  1. Click Yes to upgrade. Community first copies the database beside the original. The name includes .format2-backup-, .format3-backup- or .format4-backup- and the date and time. It adds missing schema (including the storage for Derived values), default reader mappings and the Wear area, Normal force, Cycles and Wear rate value types, then marks the notebook as format 5. Existing values, their sources and descriptions remain unchanged. Values without known conversion metadata are not assigned a guessed unit or factor.
  2. A message shows the backup path. Then the notebook opens.
  3. Click No to leave the notebook unchanged and closed. The welcome screen stays available.

Older ELN Community versions cannot open an upgraded notebook. Keep the backup copy if you must go back to an older version. The backup copies only the database; the attachment directory is not copied and does not change.

Preferences cannot relocate storage. When you move a closed notebook, move the folder that contains both the database and its attachment directory. The saved relative path then finds the directory at the new location. If you move them separately, select the attachment directory when Community asks for it.

Notebook records are stored in the database as you complete their edit commands. There is no separate Save Notebook step. Normal shutdown does not show a temporary-directory retention notice.

Local identity and signing

Notebook creation records the name supplied in the local-profile dialog and creates one ordinary local identity. No Admin promotion or team account is needed. The current Community desktop has no separate profile-edit command. Use the original signing password for record signing; opening a notebook does not request it.

Make a consistent backup

  1. Save intended changes. Resolve editor conflicts and note any retained draft or recovery directory.
  2. Close the notebook and stop all Desktop and MCP processes that use it. Do not copy a database while a writer is active.
  3. Copy the database and the entire attachment directory into one backup set. Keep their association clear.
  4. Copy any retained working-draft/recovery directory separately if it contains changes you still need. A draft is not part of the saved attachment tree.
  5. Restore into a new location, not over an open notebook. Open the restored database with the restored attachment directory and check representative records and attachments before relying on it.

Do not delete -journal, -wal or -shm files to make Open succeed. Close or recover the database in its owning client first. Preserve the database, sidecars and attachments if recovery is needed.

Scientific package export and PDF export are not full notebook backups. The current package importer restores only its supported metadata/protocol subset, not a complete record/file/value hierarchy. See reports and packages.

Launch with explicit paths

ELNCommunity.exe --config "C:\ELNExample\desktop.ini" --notebook "C:\ELNExample\notebook.sqlite" --storage "C:\ELNExample\attachments" --plugins "C:\ELNExample\plugins"

These are illustrative paths; create or select your own existing notebook and runtime plugin directory. --storage is necessary only for a notebook without a saved attachment directory, or to use a different directory for this run; it needs --notebook. --config selects the local settings file. Explicit notebook paths take priority over the last notebook. Without these arguments, Community reopens the last successfully opened notebook. On first use, choose New Notebook or Open Notebook. If the last notebook is unavailable, Community explains the problem and leaves the welcome screen usable; it does not create a replacement notebook. See troubleshooting for validation errors.
