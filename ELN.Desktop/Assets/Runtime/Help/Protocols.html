Protocols

A protocol is a structured scientific entry attached to an item. It can use a form template or free text. Open a notebook and select an item in an active project before you add one.

Create and edit a protocol

  1. Select the parent item. Choose Item > Add Protocol.
  2. In Select Template, select a category and template, then click OK. Cancel the selector if you do not want to create the protocol.
  3. In Protocol Editor, check Title, Protocol Type, Validation Status and Template. Complete the displayed form.
  4. Click Save. Select the protocol in the item tree to inspect its content. Use Edit to reopen it.

The editor supports (No template) for free text. Template forms can receive initial item and scientist information. Check all automatic entries before review.

Changing Template clears the saved form data in the editor. Do not switch templates to inspect alternatives after you have entered important content.

The editor marks unsaved changes with an asterisk. When you close a changed protocol, it asks whether to save. Choose Cancel to stay in the editor.

Review states

StateNext step
DraftComplete the record. Select In Review in Validation Status and Save.
In ReviewRead the record, then Approve or Reject.
RejectedRead the rejection reason. Change to Draft, save, correct the content and send it for review again.
ApprovedThe protocol is read-only. It cannot return to another state.

Use the review queue

  1. Choose Tools > Protocol Review....
  2. Use Filter and Refresh to find the record.
  3. Select the protocol and read its preview. Use Edit... when you need the editor.
  4. Click Approve and confirm, or click Reject and enter the rejection reason.

Use History... in a saved protocol's editor to inspect the status dates, changes, user ID and comments. History records state changes; it is not a full text-version comparison.

Community review is a local human check by the active scientist on their own record in an active owned project. It is not multi-user authorization or independent team approval. Do the human review in the desktop application; MCP cannot execute human gates.

If the record changed before a decision, reload it and read it again. Do not bypass a conflict or a disabled decision. Imported protocols start as Draft even if the package contains an approval state.
