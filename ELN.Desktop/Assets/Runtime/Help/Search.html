Search and navigation

Open a notebook first. Search reads notebook records; it does not change them. Use panel filters for the current view, Search... for notebook-wide text matches, and Go to Item... for a known ID or internal URL.

Search notebook text

  1. Choose Navigate > Search....
  2. Enter at least two characters, then click Search or press Enter. Click the arrow at the right of the box to repeat one of your last 20 searches. The box also completes from these searches as you type.
  3. Read the results: ID is the owning item ID; Type identifies an item, entry, file, value or tag match; Name shows the matching record; Location shows its project, folder and parent item; Matched In identifies the field.
  4. Select a row, by click or with the arrow keys. The main window shows its owning item. The Search window stays open, so you can check the next row. Press Esc or close the window when you are done.

The search covers item titles, descriptions and properties; entry titles; attachment titles; value descriptions; and tag names. Deleted items are excluded. Results are limited to projects the active identity can read.

Search first looks for the complete entered phrase as a substring. If a multi-word phrase has no matches, it searches individual words and returns items that match all usable words. Words shorter than two characters are skipped in this fallback. Matches can come from different fields of the same item.

This is record text search, not a search of every attachment's bytes. It does not parse PDF text, Markdown bodies or scientific file contents for the search box. Value search matches descriptions, not a numeric range. Wildcard-like characters are treated as literal search text. Do not assume Boolean operators or a query language.

Search by meaning

Search by meaning finds records that have the same sense as your words, also when the exact words are not in the record. It reads item titles, descriptions and properties, tags, entries, protocol forms, value descriptions, and the names and text of attached files. It works in the same notebook-wide scope as the text search and uses the same project access.

Semantic search is local. The files are downloaded one time (about 666 MB). About 549 MB are needed for the search. The rest is optional: PDFium, and a model that sorts the best results again (see Rerank results). After the download, the search works offline, and no notebook text leaves the computer. The search index is a copy of the notebook text. It is a file next to the notebook, with the extension .search.sqlite. Keep it in a place with the same protection as the notebook.

PDF, Office and other file types that are read

The program reads the text of these attachments: PDF, .docx, .pptx, .xlsx, .html, .htm, .json, .xml, .csv, .rtf, .md and .txt. PDF text is read with PDFium, which is an optional part of the download. The search works without PDFium, but then the PDF text is not read. Other files are found only by their names.

  • A file larger than 64 MB is not read.
  • The program keeps the first 200000 characters of each file. A PDF is read up to 2000 pages.
  • An encrypted or password-protected file is skipped. A damaged file is skipped.
  • A scanned PDF that has only images has no text. The program does not do text recognition (OCR).
  • Old Office files (.doc, .xls, .ppt) are not read.

A file that cannot be read never stops the update of the index. The program reads a file again only when its size or its last-write time changes. If only the time changes, the program checks the content before it reads the text again. The notebook is not changed.

Set up search by meaning

  1. Open a notebook, then choose Tools > Semantic Search Setup.... The list shows each part, its license, its size and its state. The state of an optional part does not stop the search. When only optional parts are missing, the state line says Installed (optional parts missing).
  2. Click Download and Install. The program downloads the parts that are needed for the search first, then the optional parts. Click Cancel to stop the download. Completed files are kept. The file that was in progress downloads again from the start. If your network uses a proxy, set the HTTPS_PROXY, HTTP_PROXY and NO_PROXY environment variables, or use the Windows proxy setting.
  3. Click Verify to check the size and checksum of each file. Remove deletes the downloaded files.

When the files are ready, the index updates when you open a notebook and when you open the Search dialog. The first update of a large notebook takes time. The program does not change the notebook for this.

Use search by meaning

In the Search dialog, select Search by meaning. The program remembers your choice. A status line shows if the index is complete or if it is still catching up. The results are ranked, and the search always shows the best matches, also when no match is close. Each item has one row. The field and the text of the row come from the best passage of the item. The dialog orders the rows by a rank-fusion score. It does not show the score. It is not a probability and it is not a relevance percentage. Read the matched field before you trust a result. A short text in another language can rank low.

Rerank results

When the optional reranking model is installed, the Search dialog has the check box Rerank results. It is on by default. The program remembers your choice. The check box works only when Search by meaning is on. Without the model, the check box is disabled and the search uses the normal order.

With Rerank results on, the program first finds the best 20 items with the normal search. Then a second model reads your words and the best passage of each item, together with the location of the item (project, folders, item title and type). The model sorts the 20 items again. The items after the first 20 keep their order. When the order comes from the model, the count above the list ends with reranked. The model does not show a score. It is not a probability.

The model takes about half a second for 20 items on a current computer. If it needs more than 1.5 seconds, or if it fails, the dialog shows the normal order. In this case the count does not say reranked. The first search after the program starts takes more time, because the program loads the model. The model can place a very short query, for example two letters, lower than the normal search does. Switch Rerank results off for such a query.

The search runs in the background. While it runs, the count shows Searching..., and you can use the window. If you start a new search, the program ignores the results of the older search.

Narrow the search

Under the search box, there are three filters: Project, Type (the item type) and Created (a first day and a last day). Use the check box of a date to turn the limit on. The filters work only when Search by meaning is on. When it is off, the filters are disabled and the text search ignores them. The filters keep their values when you open the Search window again. The filters are applied before the ranking. A strict filter therefore finds matching items that a search without a filter would rank low. The list of projects shows only the projects that you can read. The days are UTC days: the program compares them with the creation time of an item in UTC, not in your time zone. The last day includes the whole day. If the first day is after the last day, the dialog shows an error in the status line. Filters on recorded values are available in the MCP tool search_semantic, not in this dialog.

The program reads the notebook text on the main thread during an update. A large notebook can make the window pause for a short time. Each program that loads the model (Desktop, and the MCP server) uses about 1 GB of memory. This value is an estimate. The measurement is not done yet. The reranking model, when it is installed, loads at the first search with Rerank results and adds about 220 MB.

Filter the panels

  • The project-panel filter matches project titles and descriptions, or folder titles and descriptions. It keeps the matching project or folder structure visible.
  • The middle-panel Filter items... box matches item titles and descriptions, entry titles, and file titles and descriptions in the selected location. Parent rows can remain so a matched child has context.
  • Use the clear button beside a filter, or delete its text, to restore the unfiltered view.
  • Show Archived is separate from text filtering. Enable it when an archived project is missing.
  • Use Refresh to reload current records. A filter is not a record deletion.

Panel filters do not provide numeric comparisons, type selectors or tag-query syntax. Their scope differs from notebook-wide Search, so a search result can exist even when a panel filter does not match it.

Structured selection

The desktop Search dialog has a text box and three filters (project, type and creation date), not a structured scientific-query builder. For recorded conditions and results, select a project or folder and use Tools > Analysis...; see Analysis and reports. This does not make the text search a numeric search.

The optional local MCP interface provides explicit structured parameters: list_items takes project_id and can filter by folder_id, item_type and level. Its search tool takes a text query and can limit results by project_id. These are tool parameters, not expressions to paste into the desktop search box. See MCP for prerequisites and scope.

Go to a known item

  1. Choose Navigate > Go to Item....
  2. In Enter an item ID or eln:// URL:, enter a positive item ID, or an internal URL copied from a record.
  3. Click OK. If the target cannot be resolved, read the error and correct the input. Cancel closes the dialog without navigation.

Internal links use an item ID or a specimen title. They are resolved in the active notebook. An ID from another notebook is not a portable record reference. This command does not open a different notebook.

Other navigation paths

Select a project or folder in the left tree, then select an item in the middle tree. Favorites can take you back to bookmarked locations. Click an inline item relationship, or open its Links... dialog and click Open, to select its target. Rendered Wiki links use the same host navigation route.

For missing records, clear filters, check archive state, and check the Recycle Bin. See Tags and links for bookmarks and typed relationships.
