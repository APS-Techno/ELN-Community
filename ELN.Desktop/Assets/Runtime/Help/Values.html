Values

A value records a scientific quantity on a procedure or action. A Condition records an input or experimental setting. A Result records an observation or calculated output. Select the correct record type; Analysis uses this distinction.

Add a value

  1. Open an active project. Select a procedure or action in the item tree.
  2. Choose Item > Add Value.
  3. Select a Category and Value type. The value-type list shows the symbol, title and stored unit.
  4. Under Record type, select Condition or Result.
  5. Enter the Value. Use a number in the listed unit, or supported unit input. Check the conversion hint below the input.
  6. Enter a numeric Tolerance and a useful Description. Click Save.

You can also use Add Value, Edit Value and Delete Value in the procedure/action dialog. Values added or edited during creation remain staged until the first parent Save. Signed items do not permit these changes.

The item tree and the details panel show repeated values in one summary. Values that have the same value type, the same record type and the same description show as the mean, the sample standard deviation and the count, for example d = 322.8 ± 22.9 nm (n=4). The values.all field of a protocol template uses the same text. This summary is calculated for display only. The stored values do not change, and the procedure/action dialog continues to list each value.

When editing an existing procedure or action, value additions, edits and deletions save immediately. Cancelling the parent dialog does not undo those value changes. Check the value and tolerance before saving or deleting it.

Units and tolerance

The selected value type defines the stored unit. The safest input is a plain number already expressed in that unit. Supported units of the same quantity can be converted to the stored unit. Convert... opens the unit converter for the selected type. Tools > Unit Converter... opens the independent converter.

A recognized incompatible unit, an invalid number, or an invalid nonblank tolerance prevents Save. The converter also refuses incompatible quantities. An unknown suffix can still be ignored by the permissive input parser, so use a supported unit and check the stored number. A missing conversion hint is not proof of a valid unit.

Mass concentration, such as mg/mL, is separate from molar concentration, such as mol/L. Conversion between them requires the substance's molar mass and is not performed by this converter.

Tolerance is a separate numeric field. It does not use the unit parser from the Value field. Enter it in the stored quantity's unit, without a unit suffix. Do not assume it is a percentage, a confidence interval or a statistical standard deviation. Use Description to explain its meaning.

Plausible range and tolerance check

A value type can have a plausible range: a minimum, a maximum, or both, in the unit of the type. An empty limit means no limit. When you click Save, the value dialog checks the number against these rules:

  • The value is below the minimum or above the maximum of its type.
  • The tolerance is larger than the magnitude of the value. Example: value 2.279e-05 with tolerance 0.0602.
  • The tolerance is more than the tolerance factor times smaller than the value. The default factor is 1000. Example: value 300 with tolerance 0.0001.

A blank or zero tolerance is not checked. If a rule fails, a message names the problem. Click Yes to store the value as entered. Click No to go back to the dialog; nothing is stored, and you can correct the value, the tolerance or the value type.

Extract Values checks the selected values against the range and tolerance rules of their types. One message lists the issues. Click No to go back to the list. Automatic extraction after Add File cannot ask, so it skips values with range or tolerance issues. Use Extract Values on that file to review them.

The Extract Values button in the viewer works only on the file shown. To extract values from several files, select the files in the item tree, right-click and choose Extract values from N files.... The program shows one dialog for each reader. Choose the keys and value types once. The program matches the values in the other files of the same reader by key name, unit and position. A value that is missing in a file, or that fails the range or tolerance check, is skipped and counted. Files of signed items are skipped. The summary shows for each reader: X values written, Y skipped.

An item keeps one Reader value for each key of each attached file. When you extract values from a file again, or when Regenerate previews reads the file again, the program updates the Reader value that this file gave before. It does not add a second value. Thus the count (n=...) in the item tree does not increase when you read the same file again. A value that you changed by hand is Manual. Extraction does not change it and adds a new Reader value. When you delete a file, the program also deletes the Reader values that the file gave to its item. Manual values stay.

Set the range in Reference Data > Value Types.... The tolerance factor applies to all value types; set it in the same editor. See reference data.

Reader mappings and conversion

Open Reference Data > Value Types... > Reader mappings... to edit the conversion table. An exact reader and key rule takes priority over a pattern rule. Without a matching rule, extraction uses the existing title-and-unit match. The emitted unit must match the rule before its factor is applied. Unmapped keys show a reason.

Both extraction paths store the converted number and check its range in the target unit. Pattern rules with <Material>, for example <Material> Thickness or Layer <Material>.<Any>, put the material in the value description. A saved Reader source keeps the original key, emitted unit, and applied factor. Later mapping edits do not change existing conversions or descriptions.

In Extract Values, select a key and then select a value type. If the reader unit and the value type unit are different, the dialog converts the value automatically when both units measure the same quantity, for example um to m or um3 to mm³. The text above Category shows the two units and the factor. If no automatic conversion exists, the text names the two units and the key stays clear. For example, A is ampere to the converter, so it does not convert to m. A temperature with an offset, for example °C to K, does not convert either.

Keep Remember choices for this reader selected to save your choices as reader mappings when you click OK. The dialog saves only the selected keys for which you chose the value type. Later extractions, also automatic extraction after Add File, use these mappings. A new choice for the same reader, key and unit replaces the old exact rule. The option needs permission to edit reference data and a reader that has an ID.

Reader standard deviation

Extraction pairs <Key> and <Key> STD from the same reader call, with identical emitted units. The main value's tolerance is STD multiplied by the absolute mapping factor. The list shows the converted tolerance. STD keys are not separate stored values.

A missing STD leaves tolerance unset. A negative, non-finite, unit-mismatched, or ambiguous STD gives a warning and leaves the main value without tolerance. An orphan STD is reported and not stored. A valid zero STD stores zero tolerance. The source check compares the main value only; it does not check tolerance drift.

ZRW friction coefficient

The ZRW viewer reads .zrw and .zrv tribometer files, with the older tab-separated header or the newer one-line header. Extraction gives Fn, Cycles, Stroke, Speed, Sampling Rate (older files), Sampling Interval (newer files), COF and COF STD. COF is the mean friction coefficient over the selected interval (by default the first coating plateau after running-in). COF STD is the population standard deviation over all samples of the same interval; it is stored as the tolerance of COF, not as a separate value.

The viewer interval panel offers Automatic (the detected plateau) or Manual start and end. Apply saves one shared interval for the file. An unsaved draft is never stored. If the shared interval was changed after you opened the file, your draft stays and you must click Reload. If the bytes of the file change, the saved interval is stale and COF is not extracted until you click Apply again, with a Manual interval or with Automatic.

Value sources

Each value records the origin of its number. Edit Value shows the source below Description.

  • Reader: Extract Values or automatic extraction after Add File stored the number. The source names the file, the reader, the reader version and the key name that gave the number.
  • Manual: a person typed the number. If you change the value or the tolerance of a Reader or Derived value, it becomes Manual. Its note keeps the previous reader, version and key, or the previous formula and version.
  • Derived: the program calculated the number from other stored values with a named formula. The source names the formula, its version and the input values.
  • Unknown: the value was recorded before notebooks stored value sources.

Add a Derived value

  1. Right-click a Proc or Action item and choose Add > Derived Value....
  2. Select the formula. The first formula is the reciprocating wear rate K = A / (2 · F · N) (wear_rate_reciprocating, version 1). The result is a Wear rate value in mm³/(N·mm).
  3. Select each role, then select a stored value for it. The list shows only values with the required value type and unit on this item or on an item below it: area needs Wear area in mm², normal_force needs Normal force in N and cycles needs Cycles without unit.
  4. The dialog shows the calculated number. You cannot type it. The wear area can be zero; force and cycles must be positive. An input can itself be a Derived value; a value that depends on itself is refused.
  5. Click Save. The value-type range check applies. No tolerance is stored.

A Derived value is a stored result, not a live formula cell. Editing or deleting an input does not update or delete that result. Use Check Value Sources... to find changed or missing inputs. Keep the old result when it is part of the scientific record; create a new Derived value when you need a result from new inputs.

Several wear profiles of one test: for the area role, select two or more Wear area values (Ctrl or Shift click). The dialog uses their mean, and the stored Derived value lists every selected area as an input. The check of value sources calculates the mean again from the current numbers of all of them. Force and cycles take one value each.

Check value sources

  1. Right-click an item in the item tree and choose Check Value Sources....
  2. The check reads each source file of the Reader values of the item and its sub-items again. It uses the reader that this version selects for the file type. It also calculates each Derived value again: with the readers of its Reader inputs, recursively for Derived inputs, with the stored number of Manual inputs and with the saved formula version.
  3. If no value differs, a message shows how many values were checked. Otherwise a list shows each value that differs: value ID, item, file, key, the differences, the stored and current numbers, and the stored and current readers with their versions. For a Derived value, the key and reader columns show the formula and its versions.

The differences are value_changed, reader_version_changed, reader_changed, key_missing, file_missing, read_failed, reader_units_changed, source_changed, selection_changed and interval_unusable. New Reader values are checked after their saved conversion. A changed unit is reported without applying the old factor. Legacy Reader values without conversion metadata retain raw-output comparison. The check does not change a value.

For Derived values the differences are value_changed, input_changed (an input now differs from the number that was used), input_missing, formula_version_changed (a newer formula version exists; the saved version was used), formula_version_mismatch (the saved version is not available; the value is not calculated again), dependency_cycle, read_failed and not_fully_rerunnable (a Manual or Unknown value is in the input tree, so the check cannot repeat the whole calculation from files).

A value that was saved with an analysis snapshot, such as a ZRW COF, is calculated again over the interval stored in its snapshot, also when the file changed. source_changed means that the file differs from the file in the snapshot. selection_changed means that the shared interval of the file now differs from the snapshot; a file without a shared interval counts as a change only for a manually set snapshot. interval_unusable means that the stored interval holds fewer than two samples in the current file; the number is then not compared. Each difference is reported separately from value_changed.

Scientific package export writes the value and tolerance as numbers. PDF reports include the recorded values and tolerances. These outputs do not calculate new uncertainty estimates. The current package importer does not restore value rows; see package limitations.

Choose and check value types

If a required quantity is not available, use Reference Data > Value Types... to inspect the catalog. Check the symbol and unit before you add a new type. Do not select an unrelated type only to make a record fit.
