Values

A value records a scientific quantity on a procedure or action. A Condition records an input or experimental setting. A Result records an observation or calculated output. Select the correct record type; Analysis uses this distinction.

Add a value

  1. Open an active project. Select a procedure or action in the item tree.
  2. Choose Item > Add Value.
  3. Select a Category and Value type. The value-type list shows the symbol, title and stored unit.
  4. Under Record type, select Condition or Result.
  5. Enter the Value. Use a number in the listed unit, or supported unit input. Check the conversion hint below the input.
  6. Enter a numeric Tolerance and a useful Description. Click Save.

You can also use Add Value, Edit Value and Delete Value in the procedure/action dialog. Values added or edited during creation remain staged until the first parent Save. Signed items do not permit these changes.

When editing an existing procedure or action, value additions, edits and deletions save immediately. Cancelling the parent dialog does not undo those value changes. Check the value and tolerance before saving or deleting it.

Units and tolerance

The selected value type defines the stored unit. The safest input is a plain number already expressed in that unit. Supported units of the same quantity can be converted to the stored unit. Convert... opens the unit converter for the selected type. Tools > Unit Converter... opens the independent converter.

A recognized incompatible unit, an invalid number, or an invalid nonblank tolerance prevents Save. The converter also refuses incompatible quantities. An unknown suffix can still be ignored by the permissive input parser, so use a supported unit and check the stored number. A missing conversion hint is not proof of a valid unit.

Mass concentration, such as mg/mL, is separate from molar concentration, such as mol/L. Conversion between them requires the substance's molar mass and is not performed by this converter.

Tolerance is a separate numeric field. It does not use the unit parser from the Value field. Enter it in the stored quantity's unit, without a unit suffix. Do not assume it is a percentage, a confidence interval or a statistical standard deviation. Use Description to explain its meaning.

Plausible range and tolerance check

A value type can have a plausible range: a minimum, a maximum, or both, in the unit of the type. An empty limit means no limit. When you click Save, the value dialog checks the number against these rules:

  • The value is below the minimum or above the maximum of its type.
  • The tolerance is larger than the magnitude of the value. Example: value 2.279e-05 with tolerance 0.0602.
  • The tolerance is more than the tolerance factor times smaller than the value. The default factor is 1000. Example: value 300 with tolerance 0.0001.

A blank or zero tolerance is not checked. If a rule fails, a message names the problem. Click Yes to store the value as entered. Click No to go back to the dialog; nothing is stored, and you can correct the value, the tolerance or the value type.

Extract Values checks the selected values against the range of their types. One message lists all values outside their range. Click No to go back to the list. Automatic extraction after Add File cannot ask, so it does not store a value outside its range; the status bar shows how many values it skipped. Use Extract Values on that file to review them.

Set the range in Reference Data > Value Types.... The tolerance factor applies to all value types; set it in the same editor. See reference data.

Value sources

Each value records the origin of its number. Edit Value shows the source below Description.

  • Reader: Extract Values or automatic extraction after Add File stored the number. The source names the file, the reader, the reader version and the key name that gave the number.
  • Manual: a person typed the number. If you change the value or the tolerance of a Reader value, it becomes Manual. Its note keeps the previous reader, version and key.
  • Unknown: the value was recorded before notebooks stored value sources.

Check value sources

  1. Right-click an item in the item tree and choose Check Value Sources....
  2. The check reads each source file of the Reader values of the item and its sub-items again. It uses the reader that this version selects for the file type.
  3. If no value differs, a message shows how many reader values were checked. Otherwise a list shows each value that differs: value ID, item, file, key, the differences, the stored and current numbers, and the stored and current readers with their versions.

The differences are value_changed, reader_version_changed, reader_changed, key_missing, file_missing and read_failed. The check does not change a value. For each listed value, decide if you keep it, correct it or extract it again.

Scientific package export writes the value and tolerance as numbers. PDF reports include the recorded values and tolerances. These outputs do not calculate new uncertainty estimates. The current package importer does not restore value rows; see package limitations.

Choose and check value types

If a required quantity is not available, use Reference Data > Value Types... to inspect the catalog. Check the symbol and unit before you add a new type. Do not select an unrelated type only to make a record fit.
