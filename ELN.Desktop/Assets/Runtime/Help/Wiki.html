Wiki

A Wiki page is an item with a Markdown attachment for its body. It is not a separate website. Its body and assets stay in the notebook attachment directory. Open an active notebook before creating or editing pages.

Create a Wiki structure

  1. Select the project or project folder where the Wiki must go.
  2. Choose Project > New Wiki. Confirm Add a Wiki to …? The command applies the Wiki experiment template in that location and creates the root Markdown body.
  3. If no project or folder is selected, the command asks for a new topic-wiki title and description, creates a project, then applies the Wiki template.
  4. Expand the new structure and select its Wiki page to read the body.

The template must exist in this notebook, and the Markdown file type must be registered. If the template is missing, an existing-location request is refused. A new topic project can remain empty if seeding is unavailable or fails. Read the message before repeating the command.

A second Wiki template cannot be applied where a Wiki folder already exists. Use the existing structure, or deliberately rename or remove that folder before reapplying. Do not delete useful records only to repeat the template.

Create another page

Use New Item in the required item location and select the Wiki item type. A new Wiki item receives a Markdown body with its title as the first heading. Keep a registered .md file type in the notebook. See Items and Templates for item and template creation.

Read and edit the body

  1. Single-click the Wiki item. The host opens its first Markdown attachment in the Markdown viewer.
  2. Click Edit in that viewer to open the Markdown editor. The button is visible only when the editor plugin is loaded.
  3. Edit the Markdown source. Use headings, lists, emphasis and ordinary Markdown links as needed.
  4. Click Save, or press Ctrl+S, to save through the notebook attachment service.

Wiki attachments are not listed as file children in the item tree, and the thumbnail strip is hidden for a selected Wiki page. The item-tree Edit command edits item metadata; the Markdown viewer's Edit button edits the body.

The editor uses a working copy. A signature or a read-only or archived project can refuse saving even if the editor opens. Resolve these restrictions before editing. Reload discards edits; Save Anyway (overwrite server) replaces the current stored body only if write checks permit it. The dialog's server wording refers to the local notebook attachment. See Files and notes for all conflict and draft choices.

Add images and other assets

  1. Open the page body in the Markdown editor.
  2. Drag a local file into the editor. An image creates an image reference; another file creates a link. The file is uploaded as an attachment of the same item.
  3. For a clipboard image, press Ctrl+V. If the clipboard also contains text, the editor prefers text paste.
  4. Check the inserted reference, then save the page body.

Asset upload happens when you drop or paste, before you save the changed body. Cancelling the body edit does not undo that upload. Keep assets with their page and use the inserted relative name. The viewer resolves references against the item's attachments and makes local working copies as needed. A path to a file elsewhere on your computer is not an uploaded notebook asset.

Navigate between records

  • Use [[item:N]], with N replaced by an existing item ID, to create an internal item link.
  • Use [[specimen:CODE]], with CODE replaced by the specimen title, to create a specimen link.
  • Click the rendered link to navigate through the host to the target project, folder and item.
  • You can also use Tools > Go to Item... with an item ID or an internal ELN URL.

A link does not copy or move the target record. Missing, deleted or inaccessible targets cannot be opened. Use Search to locate the correct record. For typed relationships, use Tags and links; a Markdown link is not a typed item relationship.
